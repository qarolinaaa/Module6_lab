# Отчёт по лабороторной работе
## Тема: Защита доступа к API с использованием JWT

### 1. Цель работы

Целью данной работы является изучение методов защиты веб-API с использованием механизмов аутентификации и авторизации на основе JSON Web Token (JWT). В рамках работы необходимо разработать API для управления задачами, реализовать защиту отдельных конечных точек и проверить корректность работы системы безопасности.

### 2. Используемые технологии

В процессе разработки использовались следующие технологии:

- C#;
- ASP.NET Core Web API;
- .NET 9;
- JWT Bearer Authentication;
- Swagger / OpenAPI;
- HMAC-SHA256.

### 3. Описание разработанного приложения

В ходе работы было разработано веб-API для управления задачами (Task Management API). Приложение позволяет получать список задач, просматривать отдельную задачу, создавать новые задачи и удалять существующие.

Для представления данных используется модель `TaskItem`, содержащая следующие свойства:

- `Id` — уникальный идентификатор задачи;
- `Title` — название задачи;
- `Description` — описание задачи;
- `IsCompleted` — признак выполнения задачи.

Для проверки функциональности приложения были добавлены тестовые записи.

### 4. Реализация API

В приложении реализованы следующие конечные точки:

| Метод | Конечная точка | Назначение |
|---|---|---|
| POST | `/api/auth/login` | Аутентификация пользователя и выдача JWT |
| GET | `/api/tasks` | Получение списка задач |
| GET | `/api/tasks/{id}` | Получение задачи по идентификатору |
| POST | `/api/tasks` | Создание новой задачи |
| DELETE | `/api/tasks/{id}` | Удаление задачи |

Конечные точки получения данных доступны без аутентификации. Для создания и удаления задач предусмотрена обязательная проверка JWT-токена.

### 5. Реализация JWT-аутентификации

Для защиты API была реализована аутентификация с использованием JWT. При успешном входе пользователя сервер формирует и возвращает токен доступа.

В токен включены следующие данные:

- имя пользователя (Name);
- роль пользователя (Role);
- уникальный идентификатор токена (JTI);
- издатель токена (Issuer);
- получатель токена (Audience);
- срок действия токена.

Для формирования цифровой подписи используется алгоритм HMAC-SHA256.

При обращении к защищённым конечным точкам сервер проверяет подпись токена, его издателя, получателя и срок действия. Если токен отсутствует, изменён или просрочен, доступ к защищённым операциям запрещается.

Настройка аутентификации и авторизации выполнена в файле `Program.cs`. Логика выдачи токена реализована в `AuthController`, а обработка задач — в `TasksController`.

### 6. Тестирование и результаты

Для проверки работы приложения были рассмотрены основные сценарии:

1. Получение списка задач без токена — запрос успешно обрабатывается с кодом `200 OK`.
2. Успешная аутентификация пользователя — сервер возвращает JWT-токен.
3. Создание задачи без токена — доступ запрещается с кодом `401 Unauthorized`.
4. Создание задачи с действительным токеном — операция выполняется успешно с кодом `201 Created`.
5. Удаление задачи с действительным токеном — операция завершается с кодом `204 No Content`, если задача существует.
6. Использование изменённого токена — сервер возвращает `401 Unauthorized`.
7. Использование просроченного токена — сервер возвращает `401 Unauthorized`.

Результаты проверки демонстрируют различие между публичными и защищёнными конечными точками и подтверждают работу механизма проверки JWT.

### 7. Заключение

В результате выполнения практической работы было разработано веб-API для управления задачами на платформе ASP.NET Core Web API с использованием .NET 9.

Были реализованы аутентификация пользователя, генерация JWT-токена, проверка его подлинности и срока действия, а также защита отдельных конечных точек от неавторизованного доступа.

В ходе тестирования рассмотрены сценарии успешной авторизации и отказа в доступе при отсутствии, изменении или истечении срока действия токена.

Таким образом, цель работы достигнута. Полученные результаты позволили изучить основные принципы применения JWT для защиты веб-API.
